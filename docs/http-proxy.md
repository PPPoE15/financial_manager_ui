# HTTP-вход за внешним proxy

В FM-122 контейнер UI принимает HTTP на `80/TCP` без сертификатов. Внешний proxy
на отдельной ВМ завершает TLS, выпускает и продлевает сертификаты и перенаправляет
публичный HTTP на HTTPS. Nginx приложения сохраняет раздачу UI и маршрутизацию
`/auth/` и `/transaction/`, включая импорт. API-префиксы не удаляются.

## Настройка доверия

Внешний proxy должен сохранять исходный `Host` (включая порт, если он нестандартный)
и **перезаписывать**, а не дополнять клиентский `X-Forwarded-Proto` значением
`https` или `http` по фактическому соединению клиента. `X-Forwarded-Host` не используется
как источник Host; nginx устанавливает его сам из Host. `Forwarded` удаляется.

Создайте файл на хосте приложения, например `trusted-proxies.conf`:

```nginx
# Пример: заменить на реальный адрес отдельной ВМ proxy.
192.0.2.10/32 1;
# При необходимости добавить конкретный IPv6-адрес.
2001:db8::10/128 1;
```

Смонтируйте его read-only в `/etc/nginx/trusted-proxies.conf`. Это include внутри
`geo`, а не отдельный `server` или `http`. В образе файл существует, но доверенных
адресов нет: любой присланный `X-Forwarded-Proto` тогда игнорируется.
Для доверенного адреса допустимы только одиночные `http` и `https`;
некорректные или составные значения заменяются фактической схемой HTTP-входа.

Доверие проверяется по адресу TCP-соединения, который видит nginx (`$remote_addr`).
Убедитесь, что сеть сохраняет адрес ВМ proxy. Не добавляйте `0.0.0.0/0`, всю
Docker-сеть или общий адрес NAT, за которым могут находиться посторонние клиенты.
Если NAT скрывает источник, сначала настройте отдельный защищённый сетевой путь
от proxy; один заголовок не доказывает происхождение запроса.

Публикация `80:80`, firewall, доставка файла доверия и удаление Caddy из стеков —
FM-123. Доступ к HTTP-входу следует разрешить с ВМ proxy. Бэкенды должны принимать
proxy-заголовки только от nginx в своей защищённой сети. Ключи подписи JWT не
являются TLS-сертификатами и не удаляются.

## Проверки

```sh
docker build -t fm-ui:nginx-test .
python3 -m unittest discover -s scripts/tests -p test_nginx_http.py -v
```

Тест запускает собранный образ без сертификатов, выполняет `nginx -t`, проверяет
SPA, ресурсы и HTTP-проксирование на контролируемый бэкенд, сохранение Host и схемы,
поддельные заголовки и относительные перенаправления. Нужны работающий Docker и доступ
к образам `nginx:1.29.2` и `python:3.13-alpine`. Все контейнеры и сеть теста изолированы
уникальным именем и удаляются после проверки. `NGINX_TEST_IMAGE` позволяет указать
другой заранее собранный образ.

После настройки реальной ВМ proxy проверить HTTPS, вход, обновление сессии,
запросы API, импорт и прямое открытие вложенных страниц. Браузеру по-прежнему нужен
HTTPS (в частности, для Web Locks при обновлении сессии). Сквозная проверка
окружений, переключение и откат — FM-124; локальный тест не заменяет эту проверку.
