# FM-100 — просмотр и редактирование операций

Окно «Операции» общее для обеих карточек последних записей: нажатие на заголовок «Доходы»/«Расходы» открывает список нужного типа, нажатие на запись — тот же список с фокусом на операции. Пункт бокового меню «Мои операции» открывает расходы. Дополнительный независимый список для FM-70 не создаётся.

## Данные и ошибки

Первая порция — примерно два экрана; последующие страницы следуют next_skip, null завершает загрузку. UID дедуплицируются; смена фильтров начинает список с нуля. Это offset-пагинация: параллельная запись между страницами может изменить состав; для полной актуализации список перечитывается с начала.

Категория — нативный выпадающий список, который открывается первым нажатием на поле. После массового применения даты/категории и успешного сохранения выделение сбрасывается; при ошибке сохранения сохраняется.

Черновики отделены от серверного списка. Все изменённые строки сохраняются одним PATCH /transactions/batch, вне зависимости от чекбоксов. Более 100 изменений блокируют отправку, скрытого разбиения нет. Смена даты отправляет date; время сохраняет сервер. Очистка комментария — null. Исходная версия не обновляется чтением списка.

POST /transactions/batch-delete выполняется после подтверждения. Только результаты 204 удаляют черновики; 404/409 сохраняют ввод и требуют сверки. После network/5xx исход неизвестен, автоматического повтора нет. Отдельного GET по UID нет: сверка ищет UID по страницам общего списка без фильтров. Если UID не найден, UI не объявляет его удалённым; можно повторить сверку или явно отбросить черновик. Пользователь явно принимает серверную запись либо переносит только свои изменённые поля на новую версию, затем сохраняет снова.

После изменения обновляются полный список/total, обе карточки последних операций, таблица бюджета и график «Динамика финансов». Неизвестный результат также требует обновления чтения. Ошибка обновления после успешной записи не превращает её обратно в несохранённую.

## Проверки

Автотесты: преобразование денежных/календарных данных, пакетный API, гонки запросов и подгрузка, версии и неизвестный результат, частичное удаление, компоненты с настоящим Teleport, подтверждения и клавиатурный фокус. Результаты браузерной проверки и проверки с настоящим API фиксируются после выполнения, отдельно от тестовых ответов.

### Ручная проверка 06.11.2026

- В браузере: настольный макет и ширина 360px, редактирование суммы, сохранение и возврат фокуса. Узкий макет без горизонтальной прокрутки проверен на тестовом preview.
- На отдельном локальном стеке настоящих auth/transaction API: вход тестового пользователя; 60 расходов и 5 доходов; изменение суммы 1059 → 2059, очистка комментария, массовая смена категории и даты двух операций. Сервер сохранил время и микросекунды; версии выросли до 2/3.
- После сохранения обновились карточка, бюджет и график без перезагрузки страницы.
- Частичное удаление, конфликт версий, неизвестный результат, защита ухода и догрузка проверены автотестами. Дополнительный браузерный проход этих сценариев прерван передачей Chrome под управление пользователя; не отмечается как пройденный на настоящем API.

Ограничение сверки: поиск UID может потребовать до 201 страницы по 500 записей. Отдельный метод чтения по UID сократил бы стоимость; изменение backend-контракта вне FM-100.
