# Дневная динамика финансов (FM-88)

Карточка на обзоре использует GET /transaction/balance-history. Значения points не
пересчитываются. Неизвестные дни разрывают линию; точное значение выбранного дня доступно
в нативном select и output. Первоначальный диапазон — последние 14 дней по Москве.
Проверка дат: 2000–2099, обе границы включены, 1–366 дней, не позже сегодня Europe/Moscow.

Запросы версионируются, включая повтор и переход к невалидному диапазону; старый ответ
не меняет экран. Успешное сохранение операций вызывает reload. FM-409203 открывает
существующий «Первый шаг»; событие balance-saved обновляет график независимо от имени.

Макет: https://www.figma.com/design/FAPPJ3LrAUEY8indrAbfnV/Fin-Manager?node-id=847-3
Проверен через Chrome. Состояния загрузки, ошибок, неизвестного диапазона и узкий экран
согласованы в стиле проекта. SVG использует токены текущей темы; точные значения вынесены
в доступный элемент под графиком. Подписи оси сокращаются, точные суммы — нет.

## Проверка вручную

На отдельном backend fm_transaction_service dev caf743d и отдельной PostgreSQL 16:
- «Первый шаг»: 1000 ₽ → график загружен после POST /starting-balance.
- Через редактор создана тестовая статья; через окно расходов сохранено 1500 ₽.
- График без перезагрузки страницы показал −500 ₽; выбор предыдущего дня — 1000 ₽.
- Проверены desktop 1440px и узкий экран 360px: scrollWidth равен clientWidth.
- Поля и выбор дня получают фокус. Нативное изменение select клавишами через средство
  автоматизации не удалось подтвердить; смена значения проверена через selectOption и тесты.

Существующий локальный backend на 7083 ещё не содержит balance-history (404), поэтому
для проверки использовались отдельные контейнеры с временными ключами и тестовой БД.

## Стенд

`npm run dev`, затем `/dev/balance-history-preview.html`.
Параметры `?unknown`, `?constant`, `?error`, `?loading` показывают состояния на фикстурах.
`?api` отправляет запросы на VITE_API_URL с VITE_FM88_TEST_TOKEN из локального окружения;
использовать только с отдельной тестовой БД и временным токеном. Стенд не сохраняет токен.
