# FM-100: список и редактирование операций — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать утверждённое окно операций с подгрузкой, редактированием ячеек, атомарным сохранением и частичным массовым удалением.

**Architecture:** Расширить существующий API операций, сохранив функцию пяти последних записей. Состояние списка и черновиков хранить в composables окна, серверные значения отделять от ввода пользователя. HomeView открывает единое окно из обеих карточек и обновляет существующие отчёты по событию изменения данных.

**Tech Stack:** Vue 3, TypeScript, Tailwind, axios, Vitest, @vue/test-utils; новые библиотеки не нужны.

**Spec:** https://github.com/PPPoE15/fm-auto-dev/issues/100; контракт `contracts/transaction.openapi.yaml` и раздел FM-102 в `contracts/README.md` из fm-auto-dev/master; согласованные требования текущего чата.

## Конкретные решения реализации

- Открытие: добавить «Все операции» в каждой существующей карточке; нажатие на запись открывает это же окно с нужным типом и фокусом на строке. Для записи из последних пяти использовать GET конкретного UID, если строка уже переместилась из первой страницы; показать её отдельно от результатов фильтра, не прибавлять к total.
- Период: «За всё время» и «Выбрать период», во втором случае поля «От»/«До». Границы включительные, начало `00:00:00`, конец `23:59:59.999999`; категория — точный UID. Заголовок «Дата» переключает направление сортировки.
- На узком экране до 640px те же строки раскладываются вертикально с подписями полей; выбор и карандаш остаются у каждой записи. Панель действий переносится. Это адаптация в объёме #100, отдельного narrow-макета нет.
- Состояния загрузки, ошибок, пустого списка, конфликтов и подтверждения ухода — в существующей теме и по правилам макета; не менять основные цвета. Красной кнопке удаления добавить отдельный семантический токен, не менять существующий danger для текста ошибок.
- Чекбокс заголовка выбирает только загруженные строки; новые страницы не выбираются автоматически. Выбор может превышать 100, но применение/удаление блокируется с объяснением лимита. Более 100 черновиков допускаются без потери ввода, однако сохранение блокируется до отмены лишних правок; предоставить отмену правок отдельной строки. Чекбоксы не задают набор сохранения.
- Черновик содержит исходную Transaction, editable values и ошибки. Карандаш вычисляется по нормализованному отличию, возврат к исходному значению снимает его. Escape в ячейке возвращает значение до открытия текущего редактора; отмена правок строки возвращает сохранённую базу.
- При 409 или неизвестном результате показать исходные, введённые и актуальные значения через GET `/transactions/{uid}`. Пользователь явно выбирает актуальные значения либо подтверждает перенос своих правок на новую версию; это ещё не отправляет запись. При 404 сохранить видимый черновик и разрешить явно отбросить его. Отсутствие в фильтре/странице не использовать для таких выводов.
- При закрытии/смене типа, фильтров, сортировки и маршрута с правками: «Сохранить», «Отбросить», «Остаться»; действие продолжить только после успешного сохранения. При закрытии вкладки — штатный beforeunload: браузер не позволяет собственный трёхкнопочный диалог.
- Удаление подтверждается количеством и суммой сохранённых операций; если выбранные строки имеют правки, пояснить, что удаление также удалит их черновики. Удалять черновики только у результатов 204; 404/409 остаются с ошибками и возможностью сверки. Повтор требует нового подтверждения.
- Обновляемые данные: полный список и total, обе RecentTransactionsCard, BudgetStructureCard, BalanceHistoryCard. Последние три через существующий `onTransactionsSaved`; при неизвестном результате также перечитать, не сообщая об успехе.

## Review Focus

1. Поздний GET старого фильтра и повторный IntersectionObserver не заменяют новый список и не создают параллельных запросов (задача 2).
2. Смена даты переносит строку за фильтр; черновик при неуспехе остаётся, успех обновляет total/отчёты (задачи 3, 5).
3. Потеря ответа после commit и конфликт версии не вызывают повторной записи или скрытого обновления expected_version (задача 3).
4. Результаты удаления смешанные/все ошибочные, а также некорректный ответ: нельзя считать HTTP 200 полным успехом (задача 3).
5. 101 правка, Unicode-комментарии, границы дат и пустой ввод не приводят к разбивке атомарного сохранения или потере ввода (задачи 1, 3, 4).
